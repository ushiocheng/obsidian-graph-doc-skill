# obsidian-graph-doc

An agent skill that documents a codebase as an Obsidian vault.

Point it at a repo and it writes a `docs/` folder of small Markdown notes, one per module or other cohesive unit. Each note has YAML frontmatter and typed links to the notes it relates to (`depends_on`, `part_of`, `see_also` and a few more). Open `docs/` in Obsidian to browse it as a graph, or let a coding agent read the index and only the notes for the area it is changing.

## What a note looks like

```markdown
---
type: module
title: Session store
description: Persists login sessions and expires them.
sources:
  - src/auth/session.py
part_of:
  - "[[auth]]"
depends_on:
  - "[[db-pool]]"
verified_commit: 3f2a91c
---

# Session store

...

## Dependencies

- [[db-pool]]: sessions are stored in Postgres.
```

- `sources` ties the note to the files it describes.
- `verified_commit` records when it was last checked against them, so stale notes can be found with `git diff`.
- Typed links live in the frontmatter for tools, and are repeated in the body so Obsidian's graph and backlinks see them without plugins.

This repo's own [`docs/`](docs/index.md) was generated by the skill and serves as a live example.

## Install

Copy the skill folder into your agent's skills directory. For Claude Code:

```sh
git clone https://github.com/ushiocheng/obsidian-graph-doc-skill.git
cp -r obsidian-graph-doc-skill/skills/obsidian-graph-doc ~/.claude/skills/
```

The skill uses only the portable `name` and `description` frontmatter fields, so it should load in other agents that read the Agent Skills format. It has only been tried in Claude Code.

## Use

Ask your agent, inside the repo you want documented:

- "Document this codebase as an Obsidian vault" to generate `docs/`.
- "Validate the docs vault" to check it and refresh stale notes.

Then open `docs/` in Obsidian as a vault. Obsidian creates `docs/.obsidian/` with your personal settings and window state when you do; the skill adds that folder to `.gitignore` so it is not committed by accident.

After generating, the skill offers a short block for your `CLAUDE.md` or `AGENTS.md` that tells agents to keep notes current as they change code. It is opt-in.

## Validator

The one script in the skill checks a vault for broken links, bad frontmatter, duplicate note names, missing source files, orphans and stale notes. It needs Python 3 and nothing else.

```sh
python3 skills/obsidian-graph-doc/scripts/validate.py docs
```

## Limits

- Dependency links come from the model reading the code. There is no static analysis behind them, so check the ones that matter.
- Wikilinks are not clickable when the notes are viewed on GitHub.
- Obsidian's core graph view does not show link types; the types are in the frontmatter.
- It has been run on one small repo so far (this one).
